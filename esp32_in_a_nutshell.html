1. Introduction

The ESP32 is a low-cost system-on-chip (SoC) from Espressif Systems that combines a dual-core 32-bit Xtensa LX6 CPU (up to 240 MHz), 520 KB SRAM, 2.4 GHz Wi-Fi (802.11 b/g/n), Bluetooth (classic + BLE) and a rich set of analog and digital peripherals on one chip. It is usually bought as a module (e.g. ESP32-WROOM-32) with external SPI flash and an antenna, mounted on a development board with a USB-UART bridge.

Operating principle: the CPU runs firmware stored in external SPI flash (cached into RAM). Peripherals (GPIO, ADC, PWM, UART, I²C, SPI…) are memory-mapped and routed to pins through a GPIO matrix. The radio is driven by a protocol stack running on the same cores under FreeRTOS.

Why it matters: it is the standard entry point to IoT: sensing, control and wireless connectivity for a few dollars, with a mature toolchain (ESP-IDF, Arduino core, MicroPython).

3. Working principle

  1. Reset and boot: ROM bootloader reads strapping pins (GPIO0 low = download mode), then loads the second-stage bootloader and app from flash.
  2. Execution: FreeRTOS schedules tasks across both cores; interrupts service peripherals.
  3. Peripheral access: your code writes registers (via driver APIs); the GPIO matrix connects the peripheral signal to a physical pin.
  4. Wireless: the radio and its stack handle packets; your task exchanges data through sockets or BLE services.
  5. Power management: modes range from active (~tens of mA, with Tx bursts higher), modem-sleep, light-sleep, to deep sleep (only RTC alive).

Common misconceptions

  • “ESP32 pins tolerate 5 V.” They do not; use a divider or level shifter.
  • “The ADC is perfectly linear.” It is noticeably non-linear near the ends and needs calibration.
  • “Deep sleep keeps RAM.” Normal SRAM is lost; only RTC memory is retained.
  • “Wi-Fi works with any power supply.” Tx bursts draw several hundred mA peaks; weak supplies cause brown-out resets.

5. Key equations

ADC code (ideal)
N = floor( Vin / Vref × 2n ), LSB = Vref / 2n
n = bits (12), V in volts, N dimensionless. Derivation: the converter divides 0…Vref into 2n equal steps, so one step is Vref/2n and the code is the number of steps that fit in Vin. Limiting case: Vin = Vref saturates at 2n−1 = 4095. The real ESP32 ADC needs attenuation settings and calibration, so treat this as the ideal model.
PWM resolution and frequency
fPWM,max = fclk / 2n, duty count = D × 2n, Vavg = D × VDD
fclk = timer clock (80 MHz APB source), n = duty bits, D = duty fraction. Higher resolution lowers the maximum frequency.
Voltage divider (level shifting / battery sensing)
Vout = Vin · R2 / (R1 + R2)
Valid when the load impedance is much greater than R2. Large resistors save current but increase ADC error because of finite source impedance.
Average current and battery life
Iavg = (Iact·tact + Isleep·tsleep) / T, Life(h) = Capacity(mAh) / Iavg(mA)
Ideal estimate; ignores battery self-discharge and regulator losses.
UART throughput (8N1) and SPI time
Bytes/s = baud / 10, tSPI = bits / fSCK
8N1 = 1 start + 8 data + 1 stop = 10 bits per byte. Decibel and Nyquist: fs ≥ 2 fmax.

6. Solved problems

Problem 1 (Easy): ADC code

A 12-bit ideal ADC with Vref = 3.3 V measures 1.65 V. Find the code and the LSB.
Formula: N = Vin/Vref × 212 = (1.65/3.3) × 4096 = 0.5 × 4096 = 2048. LSB = 3.3/4096 = 0.806 mV.
Interpretation: mid-scale input gives mid-scale code; each count is under 1 mV, but real noise on the ESP32 ADC is several LSBs.

Problem 2 (Moderate): PWM setup

Using 10-bit LEDC resolution at 5 kHz with an 80 MHz clock, set 25 % duty. Find the duty count, Vavg and the maximum possible frequency.
Duty count = 0.25 × 1024 = 256. Vavg = 0.25 × 3.3 = 0.825 V. fmax = 80×106/1024 = 78.125 kHz, so 5 kHz is achievable.
Interpretation: 10-bit steps give 0.1 % duty resolution; going to 16 bits would cap the frequency near 1.22 kHz.

Problem 3 (Difficult, GATE style): battery life

An ESP32 sensor node draws 80 mA for 1 s every 10 minutes and 10 µA in deep sleep otherwise. Battery: 2000 mAh. Estimate life and the ADC code if the battery (4.2 V) is read through a 100 kΩ/100 kΩ divider with Vref = 3.3 V.
T = 600 s, tsleep = 599 s. Iavg = (80 mA·1 s + 0.01 mA·599 s)/600 s = (80 + 5.99)/600 = 0.1433 mA.
Life = 2000/0.1433 ≈ 13 955 h ≈ 581 days (ideal).
Divider: Vadc = 4.2 × 0.5 = 2.1 V; N = 2.1/3.3 × 4096 ≈ 2606. Divider current = 4.2 V/200 kΩ = 21 µA, which is more than deep-sleep current (10 µA)!
Interpretation: the sensing divider would dominate sleep power; use larger resistors with a capacitor, or switch the divider on only when sampling.
Shortcut: in duty-cycled systems, the active burst dominates. Compute the average as active charge per cycle divided by the period.

8. Interview preparation

Industry perspective: ESP32-class parts appear in smart-home products, industrial gateways, wearables and asset trackers. Real projects spend most effort on power budget, RF layout (antenna keep-out), OTA firmware updates, certification and production test, not on blinking LEDs.

Troubleshooting

  • Boot loop / “brown-out”: weak supply or missing decoupling capacitor.
  • Cannot flash: GPIO0 held wrong, or USB-UART driver missing.
  • ADC2 returns garbage: Wi-Fi is active; use ADC1 pins.
  • Random reset at power-up: external load on strapping pins (GPIO0/2/12/15).

Memory aids

“Flash pins 6 to 11: leave them alone.” “34 to 39: input only.” “Wi-Fi on, ADC2 gone.”
